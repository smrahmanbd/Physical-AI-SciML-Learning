Digital twins for transport operations

Research brief

Spoken overview
Read the transcript

A digital twin is more than a simulation. It is a model of a real road, junction or city that is continuously corrected with live data, so that at any moment it represents the current state of the real system. Operators can then look into the near future: forecast queues in the next fifteen minutes, test a new signal plan or a diversion in the twin before applying it, and plan for emergencies. The core mechanism is data assimilation, the same predict-and-correct idea as the Kalman filter, applied to a whole traffic model. Our example is a signalised approach. The queue model alone has an arrival estimate that is fifteen percent too low, so it drifts far from reality, with an error of about twenty-eight vehicles. Corrected each cycle with a noisy detector, the twin tracks the real queue within about three vehicles. When the detector fails for twenty cycles, the model carries the twin through the gap and the error grows only modestly. Twins combine physics models, machine learning for forecasting and perception, and Physical AI for control. In this module you will tune a twin and break its detector.

What makes a twin

A digital twin needs (1) a model of the physical system, (2) live data, (3) a two-way link: data update the model, and the model informs actions on the system. Without live updating it is a simulation; without a link to decisions it is a dashboard. Transport twins range from one junction to whole cities (for example, digital twins built on traffic simulators such as SUMO or Aimsun with real-time feeds).

Data assimilation in practice

Each cycle: predict the queue with the model, then correct towards the detector by a gain g. In the explorer: model alone, error ≈ 28 vehicles (it underestimates arrivals by 15%); twin with g = 0.5, ≈ 2.6 vehicles; three-cycle-ahead forecasts ≈ 9 vehicles. Too low a gain ignores data; too high follows detector noise. For large networks, ensemble Kalman filters and particle filters are used.

Try it

Set the gain to 0 (model only), then 1 (trust the detector fully) with noise 10. Which gives the best twin?

Surviving sensor failures

When the detector fails for 20 cycles, the twin keeps running the model; the error grows from about 2.6 to about 8.5 vehicles, still far better than the uncorrected model. Physics-based structure is what makes this graceful degradation possible; a pure data model would have nothing to run on. Twins should flag reduced confidence during gaps.

Uses and frontiers

Signal timing and corridor management; incident response and diversion testing; event and evacuation planning; resilience studies (floods, heat). Frontiers: learned surrogates (module 2.5) to make city-scale twins real-time, Physical AI controllers trained in twins (reinforcement learning) and transferred safely to the real world, and standards for twin validation.

Research angle

Open question: how should a city decide that a digital twin is good enough to test interventions? Validation standards for transport twins are still emerging.

Research notes

  • A digital twin is a model kept in step with a real system by live data and linked to decisions.
  • Data assimilation predicts with physics and corrects with measurements.
  • Physics structure lets a twin degrade gracefully when sensors fail.
  • Twins support signals, incidents, events and resilience; learned surrogates make them faster.

Reading list

New words

Digital twin
A model continuously updated with data from, and linked to decisions about, a real system.
Data assimilation
Combining model predictions with observations to estimate a system's state.
Graceful degradation
Continuing to work, with reduced accuracy, when parts fail.
Particle filter
A data assimilation method using many weighted model samples.
What-if analysis
Testing possible actions in a model before applying them.
