Surrogates and emulators: fast stand-ins

A surrogate learns the input–output map of a slow simulator from a few runs, then answers new questions almost instantly. Where you sample and what you assume about smoothness decide its accuracy.

Spoken overview
Read the transcript

Many scientific models are slow. A detailed traffic simulation of a city, a climate and energy model such as GCAM, or a crash simulation can take hours for a single run. Yet we often want thousands of runs: to optimise a design, explore policies, or quantify uncertainty. A surrogate model, also called an emulator or metamodel, solves this. We run the expensive model at a few carefully chosen inputs, then fit a fast model to these input–output pairs. The surrogate answers new questions in milliseconds. Common surrogates include radial basis functions, Gaussian processes, polynomial chaos and neural networks. Accuracy depends on how many runs we make, where we place them, and how smooth the true relationship is. Placing runs evenly, or using space-filling designs such as Latin hypercubes, usually beats random placement. A good surrogate also says where it is unsure, so we know where to run the full model next. In this module you will emulate an expensive function with a handful of runs and see how placement and smoothness matter.

When surrogates pay off

If one run takes an hour and a study needs 10,000 runs, the full model needs more than a year of computing. A surrogate built from 20 runs answers the rest in seconds. Surrogates pay off when runs are expensive, inputs are few (roughly up to 20), and the response is reasonably smooth.

Interpolating with radial basis functions

A radial basis function (RBF) surrogate adds a bump centred at each run: ŝ(x) = Σ wⱼ exp(−(ε(x − xⱼ))²). The weights are chosen so that ŝ passes exactly through every run. ε sets how wide the bumps are: too narrow and the surrogate dips between runs; too wide and the system becomes ill-conditioned. In the explorer, 6 evenly spaced runs give an error of about 0.05, and 10 runs about 0.006.

Try it

Use 6 runs and change ε from 0.3 to 6. Which values give a smooth, accurate surrogate? Then switch to random placement.

Designing the runs

Where you run matters as much as how many. Evenly spaced or Latin hypercube designs cover the input space; random designs leave gaps. Adaptive (active-learning) designs run the full model where the surrogate is most uncertain, which is where Gaussian processes (module 2.6) help. In Go 3 you will emulate a GCAM transport output this way.

GCAM link

Integrated assessment models such as GCAM are classic candidates for emulation: each scenario takes hours, and policy analysis needs thousands. See module 3.5.

Remember

  • A surrogate is a fast model trained on a few runs of a slow one.
  • It pays off when runs are expensive and many queries are needed.
  • Accuracy depends on the number and placement of runs and on smoothness.
  • Uncertainty-aware surrogates tell you where to run the full model next.

Words and links

New words

Surrogate model
A fast approximate model trained on input–output pairs of a slower model; also emulator or metamodel.
Radial basis function
A function that depends only on distance from a centre, used as a building block for interpolation.
Design of experiments
The choice of inputs at which to run a model or experiment.
Latin hypercube
A space-filling design that spreads runs across each input's range.
Active learning
Choosing new runs where the current model is most uncertain.
