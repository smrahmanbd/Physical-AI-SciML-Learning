Read the transcript

Go 2 is about building. Before writing a single network, set up a workflow that protects you from the most common mistakes. Step one: frame the question precisely, including what you will predict, from what inputs, and how you will judge success. Step two: gather the physics you trust and the data you have, and look at the data. Step three: split the data honestly. For time series, such as traffic counts, split by time: train on the past, validate on later data. A random split lets the model peek at hours next to the ones it is tested on, and reports an error far better than you will get in practice. Step four: build a simple baseline, such as a physics model alone or a linear regression, so you know what a fancy model must beat. Step five: add learning and physics, step by step. Step six: validate, quantify uncertainty and document everything so others can reproduce it. The toolchain is Python with NumPy, plus PyTorch or JAX for automatic differentiation. In this module you will see how a random split fools you.

Step 1–2: question, data and physics

Write a one-line question, for example: predict hourly traffic flow at detector D for the next 24 hours from the past four weeks, scored by mean absolute error. Then plot the data before modelling: daily and weekly patterns, missing hours, sensor failures. List the physics you trust (conservation of vehicles, capacity limits) and the parameters you do not know.

Step 3: split without leakage

Leakage is information from the test set sneaking into training. In the explorer, a forecaster that averages the three nearest known hours reports an error of about 90 veh/h with a random split but about 250 veh/h with a time split; its real error next week is about 400 veh/h. The time split is honest; the random split is not. Rules: split time series by time, spatial data by site, and fit any normalisation on training data only.

Try it

Switch the explorer between random and time splits. Which validation error is closer to the real error next week?

Step 4: baselines

Always build the simplest reasonable model first: yesterday's value at the same hour, a physics model alone, or a linear regression. Report your SciML model's improvement over this baseline. Many published deep-learning results shrink or vanish against a good baseline.

The toolchain

Python with NumPy and SciPy for arrays and classical solvers; PyTorch or JAX for neural networks and automatic differentiation; DeepXDE, NVIDIA PhysicsNeMo (formerly Modulus) or NeuroMANCER for physics-informed models; PySINDy for equation discovery; scikit-learn or GPyTorch for Gaussian processes. Use a virtual environment, pin versions, and fix random seeds. Every Go 2 lab has a NumPy version that runs in your browser and, where useful, a PyTorch version to download.

Setting up

A minimal environment: python -m venv sciml, then pip install numpy scipy matplotlib torch. Save it with pip freeze > requirements.txt.

Remember

  • Write the question and the success metric before modelling.
  • Split time series by time and spatial data by location to avoid leakage.
  • Always compare against a simple baseline.
  • Use Python with NumPy plus PyTorch or JAX; pin versions and seeds.

Words and links

New words

Data leakage
Information from validation or test data influencing training, giving over-optimistic results.
Baseline
A simple reference model that a new method must outperform.
Train/validation/test split
Dividing data for fitting, tuning and final evaluation.
Reproducibility
The ability of others to rerun an analysis and get the same results.
Virtual environment
An isolated Python installation with pinned package versions.
