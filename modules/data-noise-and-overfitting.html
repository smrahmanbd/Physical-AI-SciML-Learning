Data, noise and overfitting

Real data are noisy and limited. Models that are too flexible learn the noise; models that are too simple miss the pattern. Judge every model on data it has not seen.

Spoken overview
Read the transcript

Every measurement contains noise: sensor errors, rounding, random fluctuations. A model has to learn the pattern without learning the noise. If the model is too simple, say a straight line through a wave, it misses the pattern: this is underfitting. If it is too flexible, say a polynomial of degree thirteen through fifteen points, it threads every noisy point and wiggles wildly in between: this is overfitting. The training error keeps falling as the model grows, but the error on new data first falls and then rises. The best model sits in between, and where exactly depends on how much data and how much noise we have. The only honest judge is data the model has not seen: a validation or test set. Common defences against overfitting include more data, simpler models, regularisation, which penalises large weights, and early stopping. In scientific machine learning, physics is a powerful regulariser: an equation forbids many of the wiggles that noise would otherwise produce. In this module you will push a model from underfitting to overfitting.

Signal plus noise

Think of every data point as true value + noise. If you measure the same traffic flow twice, you get two slightly different numbers. A model should capture what repeats (the signal), not what does not (the noise). With 15 points of a sine wave and noise of 0.15, a cubic polynomial captures the wave well; a straight line cannot.

Training error lies

In the explorer, raising the polynomial degree from 1 to 13 lowers the training error steadily (0.48 → 0.06), but the error against the true curve first falls (to about 0.09 at degree 5) and then shoots up (to about 1.1 at degree 13). A model can look perfect on its own training data and be useless. Always keep data aside for testing.

Defences

More data lets flexible models settle down. Regularisation adds a penalty such as λ‖w‖² to the loss, discouraging extreme weights. Early stopping halts training when validation error starts to rise. Physics is the SciML defence: an equation residual penalises exactly the wiggles that noise creates, because real systems do not wiggle like that.

Common trap

Tuning a model again and again on the same test set slowly leaks the test set into the model. Keep a final test set untouched until the very end.

Remember

  • Data = signal + noise; models should learn the signal.
  • Underfitting misses the pattern; overfitting learns the noise.
  • Training error always falls with complexity; only unseen data reveal overfitting.
  • More data, regularisation, early stopping and physics all fight overfitting.

Words and links

New words

Noise
Random variation in measurements that does not repeat.
Underfitting
A model too simple to capture the pattern.
Overfitting
A model so flexible that it fits the noise.
Validation set
Data held back to choose models and settings.
Regularisation
A penalty in the loss that discourages overly complex solutions.
